## 目的

機能には満足しているが、見た目と使い心地が理由で日常的に使えていない。
見た目を iOS 標準アプリ風に作り直し、「今日」画面だけで毎日の記録（服薬・体調）と確認（残量・次回通院）が済むようにする。
体調の波を後から把握できるようにする。

## 作るもの（WHAT）

### A. 見た目（全画面）

iOS の標準アプリ（設定・リマインダー・ヘルスケア）に見える画面にする。

- 背景はグループ化リストの灰色、内容は白い角丸のまとまり（inset grouped list）。行は区切り線で分け、行ごとに影付きカードにしない。
- 画面上部は左寄せの大きなタイトル。現在の緑のグラデーション見出し（`.hero`）は廃止する。
- 文字はシステムフォント（`-apple-system`）。色は iOS のシステムカラーに合わせる。アクセント色は 1 色だけで、iOS のシステムブルー（ライト `#007AFF` / ダーク `#0A84FF`）。
  アクセント色・背景色・文字色は CSS 変数にまとめ、値を 1 か所変えれば全体が変わるようにする。
- 削除など取り消せない操作は赤（システムレッド）、未記録・残量少の強調はオレンジ（システムオレンジ）。
- ダークモード対応: `prefers-color-scheme: dark` で配色が切り替わる。ライト・ダークの両方で本文の文字が背景に対して読める。
- 下部タブバーのアイコンは、現在の記号文字（✓ ◉ □ ✎ ⚙）をやめ、線画のインライン SVG にする（絵文字・外部フォント・外部画像を使わない）。
- タップできる要素は高さ 44px 以上。
- 編集ダイアログ（`<dialog>`）も同じ見た目にそろえる（下から出るシート、上部に「キャンセル／タイトル／保存」）。
- `manifest.webmanifest` の `theme_color`・`background_color` と `index.html` の `theme-color` を新しい配色に合わせる。

### B. 「今日」画面

上から次の順に表示する。該当する内容がないセクションは、見出しごと表示しない（1 と 2 は常に表示）。

1. **日付の移動**: 表示中の日付と「前の日」「次の日」ボタン。今日より先の日には進めない。今日以外を表示しているときは「今日に戻る」を出す。
   タブを切り替えて「今日」タブに戻ったときは、今日の日付に戻る。
2. **体調**（今日を表示しているときだけ）: 1〜5 の 5 段階ボタンを横一列に並べる。ラベルは 1=とても悪い / 2=悪い / 3=ふつう / 4=良い / 5=とても良い。
   - ボタンを 1 回押すと、その時刻の経過記録（`journal`）が 1 件追加される（`condition` に押した値、`symptoms` と `note` は空）。確認ダイアログは出さない。
   - 同じ日に何度でも記録できる。今日記録した分は、ボタンの下に「14:05 体調 4」の形で新しい順に並べる。
   - 各記録に「メモを追加」（その記録の編集ダイアログを開く）と「取り消す」（その記録を削除する）を付ける。
3. **服薬**: その日の定時薬を時刻順に表示する。各行に薬名・1 回量・状態を出す。
   - 状態は「服用済み（記録時刻つき）」「見送り」「未記録」の 3 つ。
   - 未記録の行には「服用した」「見送る」ボタンを出す。
   - 記録済みの行には「取り消す」を出す。取り消すと未記録に戻り、「服用済み」を取り消した場合は残量が記録前の値に戻る。
   - 今日の表示で、予定時刻を過ぎて未記録の行は、オレンジの「未記録」表示で目立たせる。予定時刻前の未記録は通常の色にする。
   - 過去の日を表示しているときも、同じ操作で後から記録・取り消しができる（過去の日の未記録はすべてオレンジ）。
4. **頓服薬**: 各薬に「服用した」ボタン。その日に記録した分を「14:05」の形で並べ、それぞれ「取り消す」で削除できる（残量も戻る）。
   過去の日を表示しているときは、その日の記録の一覧と取り消しだけを出し、「服用した」ボタンは出さない。
5. **残量が少ない薬**（今日を表示しているときだけ）: 次の条件に当たる薬を「薬名・残り量・あと何日分（または何回分）」で表示する。
   - 定時薬（予定に表示中のもの）: `残量 ÷ (1回量 × 1日の服用回数)` を切り捨てた日数が 7 日以下。
   - 頓服薬: `残量 ÷ 1回量` を切り捨てた回数が 5 回以下。
   - 服用をやめた薬（後述 D）は対象外。
6. **次回の通院**（今日を表示しているときだけ）:
   - 次回の日時 = すべての通院記録の `date` と `nextDate` のうち、現在より後で最も近いもの。あれば日時と病院名を表示する。なければこの行は出さない。
   - 次回までにやること = 現在以前の通院記録のうち最も新しいものの `actions`。空でなければ表示する。
   - どちらもなければセクションごと表示しない。

過去の日の服薬表示の決まり:

- その日に記録（`doseLogs`）がある分は、薬が削除済み・服用をやめた薬でも、記録に残っている薬名で表示する。
- 記録がない予定の行（未記録）は、現在の薬の設定（服用時刻）から作る。ただし、その薬の登録日（`createdAt`）より前の日には出さない。

### C. 体調の推移（「経過」タブ）

「経過」タブの一番上に、体調の推移グラフを表示する。その下は現在と同じ記録の一覧。

- 横軸は日付、縦軸は体調 1〜5。1 日に複数の記録がある日は、その日の平均を 1 点として描く。記録がない日は点を描かず、線もその日をまたいでつながない。
- 表示期間を「2週間 / 1か月 / 3か月」で切り替えられる（初期値は 1 か月）。期間の右端は今日。
- 期間内に記録が 1 件もないときは、グラフの代わりに「この期間の記録はありません」と表示する。
- グラフはインライン SVG で描く（外部ライブラリを使わない）。ダークモードでも線と目盛りが読める。
- 一覧の体調表示は現在の「体調 3/5」のまま。

### D. 削除と「服用をやめた薬」

- 薬・通院・経過の編集ダイアログの一番下に、赤い「削除」ボタンを出す（新規追加のときは出さない）。押すと確認ダイアログを出し、OK で削除する。
- 薬を削除しても、過去の服用記録（`doseLogs`）は消さない。履歴には記録時の薬名で表示され続ける。
  通院記録の「処方された薬」からはその薬が消える。確認ダイアログの文面にこの 2 点を書く。
- 薬の編集ダイアログに「服用をやめた薬にする」のチェックを追加する。チェックした薬は、
  今日画面の服薬・頓服・残量の表示に出ない。「薬」タブでは一番下の「服用をやめた薬」セクションにまとめて表示し、編集でチェックを外せば元に戻る。
  通院記録の「処方された薬」と過去の履歴には表示され続ける。
- 既存の「定時薬の予定に表示する」チェックは残す（意味も変えない）。

### E. データ

- スキーマを version 4 にする。追加する項目の例: 薬の `createdAt`・`archived`、服用記録に「何日の何時の予定に対する記録か」「実際に減らした残量」を持たせる。項目名と持ち方は Codex に任せる。
- 旧データ（version 3 以前）は `normalizeStore()` で既定値を補う。既存の薬の `createdAt` は、その薬の最も古い服用記録の日時、記録がなければ移行した時点の日時とする。
- 既存の服用記録（version 3 の `id` が `<薬ID>-<年>-<月>-<日>-<時刻>` の形のもの）は、移行後もその日のその時刻の記録として今日画面・履歴に表示される。

## 不可侵（壊してはいけないもの）

- 保存キー `kusuri-log-web-v1` を変えない。既存データを初期化・上書き・欠落させない（移行で項目を足すだけ）。
- version 3 で書き出した JSON バックアップを復元できる。
- アプリは記録と表示だけを行う。薬・症状・診療内容についての判断・推奨・助言にあたる文言を出さない
  （例: 「飲み忘れています」「受診してください」「体調が悪化しています」は不可。「未記録」「残り 5 日分」のように事実だけを書く）。
- 入力データを外部へ送信しない。外部の CDN・フォント・画像・解析を読み込まない。
- 通院の料金・病院名の候補・処方薬の紐付け・Google カレンダー追加・JSON バックアップ/復元・オフライン動作は、現在と同じ操作で動く。
- `git push` をしない（push は GitHub Pages への公開になる）。コミットもしない。

## エッジ / 落とし穴

- 現在の「服用した」は残量を `Math.max(0, 残量 − 1回量)` で減らすため、残量が 1 回量より少ないときは 1 回量ぶん減っていない。取り消しで「記録前の値」に戻すには、実際に減った量を記録に持つ必要がある。
- version 3 の服用記録には、何日の何時の予定に対する記録かという項目がなく、定時薬は `id` の文字列（`<薬ID>-<年>-<月>-<日>-<時刻>`、月日はゼロ埋めなし）にしか入っていない。薬 ID は UUID でハイフンを含む。頓服の記録は `id` が UUID で `asNeeded: true`。
- 日付の区切りは端末のローカル時刻（現在の `dayKey()` と同じ）。UTC の日付で区切らない。
- 薬の服用時刻を後から変えると、過去の記録の時刻と現在の予定の時刻が一致しなくなる。その場合も過去の記録は消さずに、記録された時刻の行として表示する。
- 復元（JSON の読み込み）でも同じ移行が通ること。
- `<dialog>` 内の「削除」ボタンがフォームの送信（保存）を起こさないこと。
- Service Worker のキャッシュが残っていると古い画面が出る。検証時は DevTools で Service Worker を登録解除するか、ハード再読み込みする。
